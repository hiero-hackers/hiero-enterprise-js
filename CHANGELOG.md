# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the version is below 1.0.0, a minor release may contain breaking changes; those entries start with **Behavior change:**.

Only changes that users of the published packages would notice are recorded. Test-only changes, CI and tooling tweaks, and dependency bumps are left out, unless they change something contributors work with. All packages are versioned in lockstep, so each entry names the package it applies to.

## [Unreleased](https://github.com/hiero-hackers/hiero-enterprise-js/compare/v0.5.0...HEAD)

### Added

- Added `ContractService.updateHookStorage({ accountId | contractId, hookId, storageUpdates })`, which submits a `HookStoreTransaction` (HIP-1195) to update the storage slots (`EvmHookStorageSlot`) and mapping entries (`EvmHookMappingEntries`) of an EVM hook owned by an account or a contract. Either the owner's key or the hook's admin key must sign, via `additionalSigners`. A missing or doubled owner, a negative `hookId`, no updates, a key, value or mapping slot longer than 32 bytes or with a leading zero byte, or a mapping entry without a `key` or `preimage` is rejected with an `INPUT_INVALID` `HieroError` before anything is sent. Not schedulable. Applies to `@hiero-hackers/enterprise-core`. [#359](https://github.com/hiero-hackers/hiero-enterprise-js/issues/359) [#398](https://github.com/hiero-hackers/hiero-enterprise-js/pull/398)
- Added `hooks` to the options of `AccountService.createAccount` and `ContractService.createContract`, and `hooksToCreate` / `hooksToDelete` to the options of `AccountService.updateAccount` and `ContractService.updateContract` (and their scheduled variants), so accounts and contracts can create and delete HIP-1195 hooks. A hook needs `HookExtensionPoint.ACCOUNT_ALLOWANCE_HOOK`, a non-negative `hookId` unique within the list and an `EvmHook` with the hook contract; initial storage must be minimal words of at most 32 bytes, with a `key` or `preimage` on each mapping entry, and IDs to delete must be non-negative integers. Anything else is rejected with an `INPUT_INVALID` `HieroError` before anything is sent. The SDK classes `HookCreationDetails`, `HookExtensionPoint`, `EvmHook`, `EvmHookStorageSlot`, `EvmHookMappingEntries` and `EvmHookMappingEntry` are re-exported. The network must have hooks enabled. Applies to `@hiero-hackers/enterprise-core`. [#358](https://github.com/hiero-hackers/hiero-enterprise-js/issues/358) [#397](https://github.com/hiero-hackers/hiero-enterprise-js/pull/397)
- Added `NetworkService.estimateFee(transaction, { mode?, highVolumeThrottle? })`, which estimates any SDK transaction's fee on the mirror node (`POST /api/v1/network/fees`, HIP-1261) without submitting it. It returns plain data, `{ network: { multiplier, subtotal }, node, service, highVolumeMultiplier, total }`, with amounts as decimal strings in tinycents (USD), not tinybars. The transaction must be frozen (an unfrozen one is rejected with `INPUT_INVALID`) and is priced as it would be submitted, with its payer and signatures, so sign it first to count signature costs; a copy is estimated, because the SDK's `FeeEstimateQuery` freezes its transaction again and would drop them. `mode` is `FeeEstimateMode.INTRINSIC` (default, now exported) or `FeeEstimateMode.STATE`, and `highVolumeThrottle` is an integer from 0 to 10000 basis points; anything else is rejected with an `INPUT_INVALID` `HieroError` before anything is sent. Transaction listeners are not called. Applies to `@hiero-hackers/enterprise-core`. [#362](https://github.com/hiero-hackers/hiero-enterprise-js/issues/362) [#396](https://github.com/hiero-hackers/hiero-enterprise-js/pull/396)
- Added `ContractService.simulateContractCall(options)` and `ContractService.estimateContractGas(options)`, which run a contract call free on the mirror node's web3 API (`MirrorNodeContractCallQuery` / `MirrorNodeContractEstimateQuery`) and return the result as a `0x…` hex string or the gas estimate as a number. Options (`MirrorContractCallOptions`) take `contractId`, `functionName` + `functionParameters` or `rawFunctionParameters`, `sender` or `senderEvmAddress` (for an ECDSA alias as `msg.sender`), `value`, `gasLimit` and `gasPrice`. A missing or doubled call target, `sender` together with `senderEvmAddress`, or call data over 131072 bytes is rejected with an `INPUT_INVALID` `HieroError` before anything is sent; a revert comes back as `SDK_ERROR`. Transaction listeners are not called, since nothing reaches a consensus node. Applies to `@hiero-hackers/enterprise-core`. [#357](https://github.com/hiero-hackers/hiero-enterprise-js/issues/357) [#395](https://github.com/hiero-hackers/hiero-enterprise-js/pull/395)
- Added `ContractService.executeEthereumTransaction({ ethereumData, callDataFileId?, maxGasAllowance?, withFunctionResult? })`, which relays a signed Ethereum transaction through Hedera (`EthereumTransaction`, HIP-410), as JSON-RPC relays and wallets do. `ethereumData` is the signed RLP bytes or a signed SDK `EthereumTransactionData`; `maxGasAllowance` is the most HBAR the payer covers for gas the sender's gas price doesn't. It returns the executor result, the receipt's `contractId` (the contract created or called), and, with `withFunctionResult`, the EVM outcome from the record. Missing, empty or unsigned `ethereumData`, a malformed `callDataFileId` or a negative `maxGasAllowance` is rejected with an `INPUT_INVALID` `HieroError` before anything is sent. Applies to `@hiero-hackers/enterprise-core`. [#356](https://github.com/hiero-hackers/hiero-enterprise-js/issues/356) [#367](https://github.com/hiero-hackers/hiero-enterprise-js/pull/367)
- Added `NetworkService.getAddressBook({ fileId?, limit? })`, which reads the node address book from the mirror node's gRPC API and returns the SDK `NodeAddressBook`: each consensus node's ID, account, description, endpoints and public key. `fileId` is `0.0.102` by default or `0.0.101`, the two files the mirror node serves; another file or a `limit` that is not an integer >= 1 is rejected with an `INPUT_INVALID` `HieroError` before anything is sent. Custom networks need `mirrorNetwork` set. Applies to `@hiero-hackers/enterprise-core`. [#355](https://github.com/hiero-hackers/hiero-enterprise-js/issues/355) [#366](https://github.com/hiero-hackers/hiero-enterprise-js/pull/366)
- Added `NetworkService.generateRandom({ range? })`, which submits a `PrngTransaction` (HIP-351) and returns the executor result plus the random value read from the transaction record: `prngNumber`, an integer in `[0, range)`, when `range` is given, or `prngBytes`, 384 bits, without it. A `range` that is not an integer from 1 to 2147483647 is rejected with an `INPUT_INVALID` `HieroError` before anything is sent. If the record lookup fails after the transaction reached consensus, it throws `RESULT_MAPPING_FAILED` with the transaction ID instead of reading as a failed transaction. Applies to `@hiero-hackers/enterprise-core`. [#353](https://github.com/hiero-hackers/hiero-enterprise-js/issues/353) [#365](https://github.com/hiero-hackers/hiero-enterprise-js/pull/365)
- Added `AccountService.getAccountRecords(accountId, options?)`, which returns the records of the transactions an account paid for in the last 3 minutes, as a consensus node still holds them, as SDK `TransactionRecord`s (possibly empty). It runs through the same query path as the other consensus queries, so it takes `QueryOptions` (payer, payment caps, node targeting) and reports to transaction listeners. A missing or malformed `accountId` is rejected with an `INPUT_INVALID` `HieroError` before any query is sent. Applies to `@hiero-hackers/enterprise-core`. [#354](https://github.com/hiero-hackers/hiero-enterprise-js/issues/354) [#364](https://github.com/hiero-hackers/hiero-enterprise-js/pull/364)

### Fixed

- Fixed a local mirror node's rest-java and web3 requests going to `mirrorNodeUrl`: with `mirrorNodeUrl` set, `HieroContext` sent every mirror HTTP request to that origin, so the SDK's `FeeEstimateQuery` (`POST /api/v1/network/fees`, served on port 8084) and `MirrorNodeContractCallQuery` / `MirrorNodeContractEstimateQuery` (`POST /api/v1/contracts/call`, served on port 8545) got a 404 from a local mirror node. Only requests for the mirror REST origin are rewritten now; hosted networks serve every endpoint from one origin and are unaffected. Applies to `@hiero-hackers/enterprise-core`. [#393](https://github.com/hiero-hackers/hiero-enterprise-js/issues/393) [#394](https://github.com/hiero-hackers/hiero-enterprise-js/pull/394)
- **Behavior change:** fixed `AccountService.createAccount` and `updateAccount` (and their scheduled variants) rejecting an `autoRenewPeriod` outside 30–90 days with `INPUT_INVALID`, although the network's bounds are configuration and by default reach 8,000,001 s: an account with an 8,000,001 s period could not be created. Core now leaves the range to the network, so an out-of-range period gets the network's `AUTORENEW_DURATION_NOT_IN_RANGE` (or `INVALID_RENEWAL_PERIOD`) instead of `INPUT_INVALID`. Applies to `@hiero-hackers/enterprise-core`. [#378](https://github.com/hiero-hackers/hiero-enterprise-js/issues/378) [#386](https://github.com/hiero-hackers/hiero-enterprise-js/pull/386)
- Fixed `AccountService.updateAccount` (and `scheduleUpdateAccount`) throwing a raw `TypeError: Cannot read properties of undefined (reading 'clone')` when `accountId` is missing, because nothing checked it before the transaction was built. A missing or empty `accountId` is now rejected with an `INPUT_INVALID` `HieroError` ("accountId is required." / "accountId cannot be an empty string.") before anything is sent. Applies to `@hiero-hackers/enterprise-core`. [#379](https://github.com/hiero-hackers/hiero-enterprise-js/issues/379) [#387](https://github.com/hiero-hackers/hiero-enterprise-js/pull/387)
- Fixed `AccountService.approveNftAllowance` (and `approveAllowance`) silently dropping a `delegatingSpender` that is an empty string and approving the allowance without one. An empty or whitespace `delegatingSpender` is now rejected with an `INPUT_INVALID` `HieroError` ("nftAllowances[].delegatingSpender cannot be an empty string.") before anything is sent. Applies to `@hiero-hackers/enterprise-core`. [#380](https://github.com/hiero-hackers/hiero-enterprise-js/issues/380) [#388](https://github.com/hiero-hackers/hiero-enterprise-js/pull/388)
- Fixed `TopicService.createTopic` rejecting a topic that has an `adminKey` but no `autoRenewAccountId` with `INPUT_INVALID` ("autoRenewAccountId is required when an adminKey is set."). The network accepts such a topic, and the SDK makes the payer its auto-renew account; the HAPI rule is the reverse (no auto-renew account without an admin key), which the network still enforces. Applies to `@hiero-hackers/enterprise-core`. [#377](https://github.com/hiero-hackers/hiero-enterprise-js/issues/377) [#385](https://github.com/hiero-hackers/hiero-enterprise-js/pull/385)

## [0.5.0](https://github.com/hiero-hackers/hiero-enterprise-js/compare/v0.4.0...v0.5.0) - 2026-10-17

### Added

- Added support for SDK-format transaction IDs (`0.0.5@1700000000.000000123`, as `TransactionId.toString()` and `HieroError.transactionId` print them) in `TransactionRepository.findById` / `findAllById`, `MirrorNodeClient.queryTransaction` / `queryTransactionRows`, `queryContractResult`, `queryContractActions` and `queryContractOpcodes`. They were sent as-is and the mirror node rejected them with `400 Invalid Transaction id`; they are now rewritten to the mirror form `0.0.5-1700000000-000000123`. IDs with a `?scheduled` or `/nonce` suffix are not rewritten; use the `scheduled` / `nonce` options. Applies to `@hiero-hackers/enterprise-mirror`. [#336](https://github.com/hiero-hackers/hiero-enterprise-js/issues/336) [#348](https://github.com/hiero-hackers/hiero-enterprise-js/pull/348)
- Added `TransactionRepository.findAllById` and `MirrorNodeClient.queryTransactionRows`, which return every row the mirror node sends for a transaction ID: parent and child transactions, or a `SCHEDULECREATE` and its scheduled execution. `findById` / `queryTransaction` returned only the first row, so the scheduled execution and child transactions were unreachable. `findById` still returns the first row. Applies to `@hiero-hackers/enterprise-mirror`. [#203](https://github.com/hiero-hackers/hiero-enterprise-js/issues/203) [#326](https://github.com/hiero-hackers/hiero-enterprise-js/pull/326)
- Added `MirrorError.detail`, the mirror node's own diagnostic from an HTTP error body (`_status.messages[0]`, as `"message (detail)"`), so callers can show it — for example `CONTRACT_REVERT_EXECUTED (0x08c379a0…)` from a failed `contracts/call` — without splitting `message` at its `" — "` separator. It is `undefined` when the body carries no diagnostic; `message` is unchanged. Applies to `@hiero-hackers/enterprise-mirror`. [#209](https://github.com/hiero-hackers/hiero-enterprise-js/issues/209) [#325](https://github.com/hiero-hackers/hiero-enterprise-js/pull/325)

### Changed

- **Behavior change:** the mirror client honours `Retry-After` only up to 5 seconds. A `429` or 5xx whose `Retry-After` asks for longer now ends the request with that response's error instead of sleeping: a request with `timeoutMs: 500` used to take 5 s on `Retry-After: 5`, and `Retry-After: 60` held a concurrency slot for about 3 minutes across the default retries. Shorter `Retry-After` values are honoured as before. Applies to `@hiero-hackers/enterprise-mirror`. [#338](https://github.com/hiero-hackers/hiero-enterprise-js/issues/338) [#347](https://github.com/hiero-hackers/hiero-enterprise-js/pull/347)
- **Behavior change:** `MirrorNodeClient` (and `createMirrorNodeClient` / `HIERO_MIRROR_NODE_URL`) now throws a `CONFIG_INVALID` `MirrorError` for a base URL ending in `/api/v1` (with or without a trailing slash), naming the URL to use instead. Every request path already starts with `/api/v1`, so such a URL requested `/api/v1/api/v1/…`, got a 404 and reported every lookup as `NOT_FOUND` (or `null` through `orNull`). Applies to `@hiero-hackers/enterprise-mirror`. [#337](https://github.com/hiero-hackers/hiero-enterprise-js/issues/337) [#346](https://github.com/hiero-hackers/hiero-enterprise-js/pull/346)

### Fixed

- Fixed the mirror client's request gate briefly running more requests than `maxConcurrent` (`HIERO_MIRROR_NODE_MAX_CONCURRENT`): a finished request freed its slot before the next queued request had taken it, so a request arriving in between took the slot as well (two in flight under `maxConcurrent: 1`). A freed slot now passes directly to the next queued request. Applies to `@hiero-hackers/enterprise-mirror`. [#334](https://github.com/hiero-hackers/hiero-enterprise-js/issues/334) [#345](https://github.com/hiero-hackers/hiero-enterprise-js/pull/345)
- Fixed balance pagination (`AccountRepository.listBalances`, `TokenRepository.findHolders`, `collectAll` / `paginate` over them) skipping accounts: each next-page link got the response body's `timestamp` appended, which moved page 2 onward to the latest balance snapshot instead of current balances, so accounts created since that snapshot were silently missing (16 consecutive mainnet accounts in one observed run). The client now follows `links.next` as the mirror node sends it; a `timestamp` you pass is still kept by the mirror node in every link. Applies to `@hiero-hackers/enterprise-mirror`. [#328](https://github.com/hiero-hackers/hiero-enterprise-js/issues/328) [#344](https://github.com/hiero-hackers/hiero-enterprise-js/pull/344)
- **Behavior change:** fixed `TokenBalance.decimals` being typed `number` on the token entries of `Balance.tokens` (`AccountRepository.getBalance`) and `AccountInfo.tokenBalances`, where it was always `undefined`: the account response carries only `token_id` and `balance` per token. `TokenBalance.decimals` is now optional and is set only by the account-tokens listing (`queryAccountTokens`), which does report it. Read decimals from the token (`TokenRepository.findById`) or from that listing. Applies to `@hiero-hackers/enterprise-mirror`. [#329](https://github.com/hiero-hackers/hiero-enterprise-js/issues/329) [#343](https://github.com/hiero-hackers/hiero-enterprise-js/pull/343)
- Fixed `TransactionType` missing 35 of the 77 transaction types the mirror node can filter on, so `TransactionQuery.transactionType` rejected common values such as `ETHEREUMTRANSACTION`, `CRYPTODELETEALLOWANCE`, `TOKENCLAIMAIRDROP`, `TOKENREJECT`, `UTILPRNG` and `ATOMICBATCH` without a cast. The union now matches the spec's `TransactionTypes` enum, and a test keeps it in sync when the spec snapshot is refreshed. Applies to `@hiero-hackers/enterprise-mirror`. [#332](https://github.com/hiero-hackers/hiero-enterprise-js/issues/332) [#342](https://github.com/hiero-hackers/hiero-enterprise-js/pull/342)
- Fixed `MirrorNodeClient` accepting an invalid `timeoutMs` or `maxRetries`: a typo such as `HIERO_MIRROR_NODE_TIMEOUT_MS=10s` built a client whose every request failed with `TIMED_OUT … after NaNms`, and `HIERO_MIRROR_NODE_MAX_RETRIES=three` silently turned retries off. The constructor (and so `createMirrorNodeClient`) now throws a `CONFIG_INVALID` `MirrorError` unless `timeoutMs` is a finite number > 0 and `maxRetries` is an integer >= 0, as it already did for `maxConcurrent` and `maxRequestsPerSecond`. Applies to `@hiero-hackers/enterprise-mirror`. [#333](https://github.com/hiero-hackers/hiero-enterprise-js/issues/333) [#341](https://github.com/hiero-hackers/hiero-enterprise-js/pull/341)
- Fixed the mirror client retrying `501 Not Implemented` responses: a `501` is a fixed answer (the mirror node returns it for endpoints it does not serve), so with the default `maxRetries: 3` the client sent 4 requests and waited through 3 backoffs before throwing the same error. It now throws after the first `501`; other 5xx responses and `429` are still retried. Applies to `@hiero-hackers/enterprise-mirror`. [#335](https://github.com/hiero-hackers/hiero-enterprise-js/issues/335) [#340](https://github.com/hiero-hackers/hiero-enterprise-js/pull/340)
- Fixed `MirrorNodeClient.queryAccountBalance` and `AccountRepository.getBalance` returning the caller's input as `Balance.accountId`: looking up `0x0000000000000000000000000000000000000062` returned that EVM address instead of `0.0.98`. `accountId` now comes from the response's `account` field. Applies to `@hiero-hackers/enterprise-mirror`. [#330](https://github.com/hiero-hackers/hiero-enterprise-js/issues/330) [#339](https://github.com/hiero-hackers/hiero-enterprise-js/pull/339)
- **Behavior change:** fixed the registered-node endpoint role fields being typed `boolean`: `blockNode`, `generalService`, `mirrorNode` and `rpcRelay` on `RegisteredServiceEndpoint` (and `block_node`, `general_service`, `mirror_node`, `rpc_relay` on `MirrorRegisteredServiceEndpoint`) hold the role's details or `null`, as the mirror node sends them, so `if (endpoint.blockNode)` was an object-truthiness test and the role details were unreachable without a cast. `blockNode` is now `{ endpointApis }` and `generalService` is `{ description }`. The top-level `endpointApis` and `description` fields, which the mirror node never sends and were always `undefined`, are removed; read them from `blockNode` and `generalService`. Applies to `@hiero-hackers/enterprise-mirror`. [#208](https://github.com/hiero-hackers/hiero-enterprise-js/issues/208) [#324](https://github.com/hiero-hackers/hiero-enterprise-js/pull/324)
- **Behavior change:** fixed fields the mirror node sends as `null` reaching callers as `null` although their types did not allow it. On `MirrorAccountInfo`, `alias`, `evmAddress`, `autoRenewPeriod`, `memo`, `maxAutomaticTokenAssociations`, `stakedAccountId`, `stakedNodeId`, `stakePeriodStart` and `createdTimestamp`; on `Nft`, `createdTimestamp`, `spender` and `delegatingSpender`; and a fixed fee's `denominatingTokenId` (HBAR fees) are now `undefined` instead of `null`, so `info.alias !== undefined` and `fee.denominatingTokenId === undefined` mean what they say. `NftTransferInfo.senderAccountId` (null on mint), `NftTransferInfo.receiverAccountId` and `NftTransaction.receiverAccountId` (null on burn) are now typed `string | null`. The `Mirror*` wire types include `null` for all of them. Applies to `@hiero-hackers/enterprise-mirror`. [#331](https://github.com/hiero-hackers/hiero-enterprise-js/issues/331) [#349](https://github.com/hiero-hackers/hiero-enterprise-js/pull/349)

## [0.4.0](https://github.com/hiero-hackers/hiero-enterprise-js/compare/v0.3.0...v0.4.0) - 2026-10-15

### Added

- Added the `HIERO_REQUEST_TIMEOUT_MS`, `HIERO_GRPC_DEADLINE_MS`, `HIERO_MAX_ATTEMPTS`, `HIERO_MIN_BACKOFF_MS` and `HIERO_MAX_BACKOFF_MS` environment variables, read by `resolveConfigFromEnv` (and so by `new HieroContext()` without a config) into the matching `HieroConfig` fields. The sample `.env.example` files already listed them, but nothing read them, so setting them had no effect. A value that is not a positive number throws a `CONFIG_INVALID` error naming the variable. Applies to `@hiero-hackers/enterprise-core`. [#249](https://github.com/hiero-hackers/hiero-enterprise-js/issues/249) [#307](https://github.com/hiero-hackers/hiero-enterprise-js/pull/307)
- Exported `CreateContractFlowOptions`, `ExecuteContractOptions`, `UpdateContractOptions`, `DeleteContractOptions` and `CallContractOptions` from `@hiero-hackers/enterprise-core` (alongside the existing `CreateContractOptions`), and re-exported `FlowOptions` from the package root, so consumers can type those method arguments without reaching into internal paths. Applies to `@hiero-hackers/enterprise-core`. [#260](https://github.com/hiero-hackers/hiero-enterprise-js/issues/260) [#299](https://github.com/hiero-hackers/hiero-enterprise-js/pull/299)
- Added the `mirrorNetwork` (`HIERO_MIRROR_NETWORK`) and `mirrorNodeUrl` (`HIERO_MIRROR_NODE_URL`) options to `HieroConfig`, which point a custom network's client at its mirror node: `mirrorNetwork` sets the mirror gRPC addresses and `mirrorNodeUrl` sends the mirror REST calls (balances) to that URL. Without `mirrorNodeUrl` the SDK sends a local mirror node's REST calls to port 5551. An invalid `mirrorNodeUrl` throws a `CONFIG_INVALID` error. Applies to `@hiero-hackers/enterprise-core`. [#279](https://github.com/hiero-hackers/hiero-enterprise-js/pull/279)
- Added `AccountService.getTokenBalance(accountId, tokenId)`, which reads an account's balance of one token from the mirror node and returns `{ tokenId, balance, decimals }`; an account that doesn't hold the token returns a balance of `"0"`. Applies to `@hiero-hackers/enterprise-core`. [#279](https://github.com/hiero-hackers/hiero-enterprise-js/pull/279)
- Added an optional `QueryOptions` argument (`payerAccountId`, `maxQueryPayment`, `queryPayment`, `nodeAccountIds`) to every query sent to the consensus nodes: `AccountService.verifyAccountSignature` and `verifyAccountTransaction`; `ContractService.getContractInfo` and `getContractBytecode`; `FileService.getFileContents` and `getFileInfo`; `ScheduleService.getInfo`; `TokenService.getTokenInfo` and `getNftInfo`; and `TopicService.getTopicInfo`. Before, only `NetworkService` honoured these options, so a query could not be pinned to a node or paid for by another account. `ContractService.callContract` takes them as part of its options, and its `queryPayment` and `maxQueryPayment` now also accept a number of HBAR. Existing calls are unchanged. Applies to `@hiero-hackers/enterprise-core`. [#254](https://github.com/hiero-hackers/hiero-enterprise-js/issues/254) [#276](https://github.com/hiero-hackers/hiero-enterprise-js/pull/276)

### Changed

- **Behavior change:** `resolveConfigFromEnv` now always returns a `HieroConfig` and throws a `CONFIG_INVALID` `HieroError` listing the missing variables when a required one is unset, instead of returning `null`. Callers that checked for `null` should catch the error instead. `assertEnvConfigValid` now also rejects invalid values, not only missing ones. Applies to `@hiero-hackers/enterprise-core`. [#250](https://github.com/hiero-hackers/hiero-enterprise-js/issues/250) [#312](https://github.com/hiero-hackers/hiero-enterprise-js/pull/312)
- **Behavior change:** validation failures used to carry code `SDK_ERROR`, so callers could not tell invalid input from a network or SDK failure; they now carry the new `INPUT_INVALID` code (`HieroErrorCodes.InputInvalid`). For example, `scheduleService.sign({ scheduleId: "" })` now rejects with `code: "INPUT_INVALID"` and `context: "ScheduleSignValidator"`. This covers every service validator, the empty allowance-list checks in `AccountService`, the `functionName` / `rawFunctionParameters` check in `ContractService.callContract`, and the size check in `FileService.scheduleUpdateFile`; messages are unchanged. Code that matches on `SDK_ERROR` to detect bad input should match on `INPUT_INVALID` instead. The new `validationError(context, message)` export creates the same error. Applies to `@hiero-hackers/enterprise-core`. [#251](https://github.com/hiero-hackers/hiero-enterprise-js/issues/251) [#291](https://github.com/hiero-hackers/hiero-enterprise-js/pull/291)
- **Behavior change:** `HieroError.cause` is now typed `unknown` instead of `Error`, matching the standard `Error.cause`, and always holds the original thrown value. Before, a thrown value that wasn't an `Error` was lost: `normalizeError("oops")` and `HieroContext`'s credential errors dropped it, and `executeContract` / `autoCreateEvmAccount` replaced it with a new `Error` made from its text. TypeScript code that reads `err.cause.message` must now narrow it first, for example `err.cause instanceof Error ? err.cause.message : String(err.cause)`. Applies to `@hiero-hackers/enterprise-core`. [#261](https://github.com/hiero-hackers/hiero-enterprise-js/issues/261) [#290](https://github.com/hiero-hackers/hiero-enterprise-js/pull/290)
- **Behavior change:** `HieroContext` no longer exposes the operator private key. `context.config` is now a copy of the resolved config with `operatorKey` set to `"[redacted]"`, so logging or serializing it (`JSON.stringify(context.config)`) no longer leaks the key, and changes to `context.config` no longer reach the caller's own config object. The parsed key is now a `#private` field, so `console.log(context)` and `util.inspect(context)` no longer print it. Signing and `operatorPublicKey` are unchanged; code that read `context.config.operatorKey` should keep the key from its own config instead. Applies to `@hiero-hackers/enterprise-core`. [#258](https://github.com/hiero-hackers/hiero-enterprise-js/issues/258) [#286](https://github.com/hiero-hackers/hiero-enterprise-js/pull/286)

### Added

- Added `withFunctionResult` to `ContractService.executeContract`. A contract call's receipt only says `SUCCESS` or `CONTRACT_REVERT_EXECUTED`; with `withFunctionResult: true` the method also fetches the transaction record (one extra paid query) and returns `functionResult` with `returnDataHex`, `gasUsed` and `errorMessage`. Without the flag, `functionResult` is `null` and no extra query is made. Applies to `@hiero-hackers/enterprise-core`. [#166](https://github.com/hiero-hackers/hiero-enterprise-js/pull/166)
- Added an opt-in `retryOn404` option (`HIERO_MIRROR_NODE_RETRY_ON_404`) to `MirrorNodeClient`. The mirror node is eventually consistent, so reading an entity right after creating it can return a 404 until the mirror node imports it; with the option enabled, a 404 is retried on the existing retry budget and backoff. The default is unchanged: a 404 is final and throws `NOT_FOUND`. Applies to `@hiero-hackers/enterprise-mirror`. [#130](https://github.com/hiero-hackers/hiero-enterprise-js/issues/130) [#158](https://github.com/hiero-hackers/hiero-enterprise-js/pull/158)

[#145](https://github.com/hiero-hackers/hiero-enterprise-js/issues/145) [#146](https://github.com/hiero-hackers/hiero-enterprise-js/pull/146)

### Changed

- **Behavior change:** write operations now return a result instead of `void`. Every write returns `{ response, receipt, transactionId, status }` plus the operation's own values from the receipt, for example the new entity ID from a create. Return types that changed: `mintToken` returns `{ serials: number[], totalSupply: string }` instead of `Long[]`; `burnToken` and `wipeToken` return `{ totalSupply: string }` instead of `Long`; allowance operations return the shared fields instead of the raw receipt; `submitMessage` returns `sequenceNumber` as a `number` (or `null`) instead of a `Long`, plus `runningHash`. Scheduled variants return the shared fields plus `scheduleId` as an SDK `ScheduleId` instead of a string, and the `ScheduledResult` type was removed; call `scheduleId.toString()` where a string is needed. Applies to `@hiero-hackers/enterprise-core`. [#134](https://github.com/hiero-hackers/hiero-enterprise-js/issues/134) [#143](https://github.com/hiero-hackers/hiero-enterprise-js/pull/143)
- **Behavior change:** `AccountService.autoCreateEvmAccount` now returns the created `accountId` (or `null` when the EVM address already had an account). If the transfer reached consensus but the child-receipt lookup fails, it throws a `HieroError` with the new code `RESULT_MAPPING_FAILED` and the `transactionId`; do not resubmit, because the transfer already happened. Applies to `@hiero-hackers/enterprise-core`. [#167](https://github.com/hiero-hackers/hiero-enterprise-js/pull/167)

Amount fields are now decimal strings instead of numbers, `Balance.hbars` was renamed to `Balance.tinybars`, and the unit helpers return strings. Use `BigInt(amount)` where you do arithmetic. Fields bounded by the protocol stay numbers. Applies to `@hiero-hackers/enterprise-mirror`. ## [0.1.0](https://github.com/hiero-hackers/hiero-enterprise-js/releases/tag/v0.1.0) - 2026-07-16

First published release, under the `@hiero-hackers` scope on the GitHub Packages npm registry.

### Added

- Added `@hiero-hackers/enterprise-core`, typed services over the Hiero SDK, configured from code or `HIERO_*` environment variables, with ED25519, ECDSA and DER operator keys and custom networks via `HIERO_NETWORK_NODES`. Every operation validates its input before building the transaction, failures are reported as `HieroError` with a machine-readable `code`, and transaction listeners receive before and after events. Any write can also be scheduled.
    - `AccountService`: create (native, EVM and alias accounts), update, delete, transfers, HBAR, token and NFT allowances, balances, and verifying signatures and transactions against an account's on-chain key.
    - `TokenService`: create, mint, burn, wipe, associate, dissociate, update, delete, freeze and unfreeze, grant and revoke KYC, pause and unpause, fee-schedule updates, NFT metadata updates, token reject, fungible and NFT airdrops (send, claim, cancel), and token and NFT info queries.
    - `ContractService`: create, create-flow for large bytecode, execute, update, delete, and bytecode, info and local-call queries.
    - `TopicService`: create, update, delete, submit message, topic info and message subscriptions.
    - `FileService`: create, append, update, delete, and contents and info queries, with large contents split across transactions automatically.
    - `ScheduleService` (sign, cancel, info) and `NetworkService`.
- Added `@hiero-hackers/enterprise-mirror`, a dependency-free mirror node REST client covering the complete mirror node REST API, with typed repositories for accounts, blocks, contracts, NFTs, tokens, topics, transactions, schedules and network data, pagination in both directions, rate limiting, retries and timeouts, filters, and unit helpers. [#111](https://github.com/hiero-hackers/hiero-enterprise-js/pull/111)
- Added `@hiero-hackers/enterprise-express`, `@hiero-hackers/enterprise-fastify` and `@hiero-hackers/enterprise-nest`, framework integrations that expose the core services and mirror repositories as `req.hiero`, `fastify.hiero` and NestJS providers.
- Added sample Express, Fastify and NestJS apps and a gallery of standalone example scripts.
